Marco del proyecto

Prototipo de plataforma de datos meteorológicos
para el análisis de islas de calor en Mérida

Objetivo

Diseñar e implementar un prototipo de plataforma en línea para la integración, almacenamiento y visualización de datos meteorológicos provenientes de diversas fuentes públicas en México, dejando preparada la infraestructura de datos para la futura incorporación de información generada por dispositivos de medición, con el fin de apoyar el análisis de islas de calor en la ciudad de Mérida.

Descripción

El proyecto consiste en el desarrollo de un prototipo de plataforma en línea orientada a la gestión de datos meteorológicos, integrando información histórica y actual proveniente de distintas bases de datos públicas disponibles en México. La plataforma permitirá el almacenamiento estructurado, consulta y visualización de variables como temperatura, humedad relativa, radiación y evapotranspiración. Asimismo, se diseñará el modelo de datos y la arquitectura necesaria para el registro futuro de información capturada por un dispositivo de medición meteorológica que será desarrollado posteriormente. El proyecto tiene como finalidad sentar las bases para el análisis espacial y temporal de islas de calor urbano en Mérida, integrando principios de ingeniería de datos y sistemas de información.

02
Contexto científico

¿Qué es una isla de calor urbana?

Una isla de calor urbana (UHI · Urban Heat Island) es el fenómeno por el cual las ciudades registran temperaturas significativamente más altas que las zonas rurales o vegetadas circundantes. El asfalto, el concreto y la ausencia de vegetación absorben y re-emiten calor, elevando hasta 10 °C la temperatura efectiva en horarios pico.

En la Península de Yucatán este efecto se intensifica por la combinación de radiación solar elevada, humedad ambiental y crecimiento urbano acelerado. La plataforma Islas de Calor documenta, mide y visualiza este fenómeno de manera abierta para informar políticas públicas, decisiones urbanísticas y esfuerzos comunitarios de adaptación al cambio climático.

  • Datos abiertos — todas las mediciones están disponibles vía API REST y descargas en CSV/Excel.
  • Tiempo real — pipeline ETL automatizado cada 5 minutos.
  • Geo-referenciado — interpolación espacial sobre grid de 2,500 puntos.
  • Reproducible — metodología publicada y código abierto.

Documentación API · Islas de Calor

Enviar mediciones a la base de datos

Para agregar información a la base, los dispositivos sensores envían un POST con un JSON al endpoint /api/sensores. Cada llamada inserta una fila nueva en la colección SensoresRaw; el pipeline ETL la procesa automáticamente cada 5 minutos.

Requiere autenticación HTTP Basic
Todas las llamadas a /api/* requieren credenciales. Usuario: publico · Password: islas2026 (configurables vía API_USER / API_PASS en el .env del servidor).
POST http://127.0.0.1:8000/api/sensores

Recibe una medición individual desde un dispositivo y la persiste en MongoDB con timestamp UTC asignado por el servidor. Requiere autenticación.

3 · Loop continuo de telemetría

Patrón típico en dispositivos IoT que miden y envían cada N segundos. Sustituye leer_sensor() por la lectura real del hardware.

Python · sensor_loop.py 
import time
import requests

API_URL    = "http://127.0.0.1:8000/api/sensores"
API_AUTH   = ("publico", "islas2026")
DEVICE_ID  = "sensor-07"
LAT, LON   = 20.9742, -89.6213
INTERVALO  = 60   # segundos entre envíos


def leer_sensor():
    """Sustituir por la lectura real del hardware (DHT22, BME280, etc.)."""
    return {
        "temperatura": 34.8,
        "humedad":     48.2,
        "salinidad":   0.61,
        "radiacion":   820.0,
    }


def enviar(medicion):
    payload = {
        "device_id": DEVICE_ID,
        "lat": LAT, "lon": LON,
        "estado": "activo",
        **medicion,
    }
    try:
        r = requests.post(API_URL, json=payload, auth=API_AUTH, timeout=10)
        r.raise_for_status()
        return True
    except requests.RequestException as e:
        print(f"[{time.strftime('%H:%M:%S')}] error: {e}")
        return False


if __name__ == "__main__":
    while True:
        med = leer_sensor()
        ok  = enviar(med)
        print(f"[{time.strftime('%H:%M:%S')}]  t={med['temperatura']}°C  h={med['humedad']}%  enviado={ok}")
        time.sleep(INTERVALO)

4 · Resiliente · reintentos + buffer local

Para redes inestables (WiFi externo, LTE). Si la API está caída, guarda en disco y reintenta cuando vuelva.

Python · sensor_resiliente.py 
import json
import pathlib
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

API_URL  = "http://127.0.0.1:8000/api/sensores"
API_AUTH = ("publico", "islas2026")
BUFFER   = pathlib.Path("./pendientes.jsonl")

# Sesión con reintentos automáticos (backoff exponencial)
session = requests.Session()
session.auth = API_AUTH
retries = Retry(
    total=5,
    backoff_factor=1.5,            # 1.5, 3, 4.5, 6, 7.5 s
    status_forcelist=[502, 503, 504],
    allowed_methods=["POST"],
)
session.mount("http://",  HTTPAdapter(max_retries=retries))
session.mount("https://", HTTPAdapter(max_retries=retries))


def guardar_buffer(payload):
    """Persistir si la API no respondió."""
    with BUFFER.open("a", encoding="utf-8") as f:
        f.write(json.dumps(payload) + "\n")


def vaciar_buffer():
    """Reintentar pendientes acumulados."""
    if not BUFFER.exists():
        return
    quedan = []
    for linea in BUFFER.read_text().splitlines():
        try:
            session.post(API_URL, json=json.loads(linea), timeout=10).raise_for_status()
        except requests.RequestException:
            quedan.append(linea)
    BUFFER.write_text("\n".join(quedan) + ("\n" if quedan else ""))


def enviar(payload):
    try:
        session.post(API_URL, json=payload, timeout=10).raise_for_status()
        vaciar_buffer()
        print("ok")
    except requests.RequestException as e:
        print("API caída, guardando local:", e)
        guardar_buffer(payload)

    "device_id":   "sensor-07",
    "temperatura": 34.8, "humedad": 48.2,
    "salinidad":   0.61, "radiacion": 820.0,
    "lat": 20.9742, "lon": -89.6213,

5 · Cliente reutilizable (clase)

Una clase que encapsula la sesión HTTP, el device_id y la geolocalización.

Python · islas_client.py 
from dataclasses import dataclass, field
import requests


def _new_session(user="publico", password="islas2026"):
    s = requests.Session()
    s.auth = (user, password)
    return s


@dataclass
class IslasClient:
    base_url:  str = "http://127.0.0.1:8000"
    device_id: str = "sensor-XX"
    lat:       float = 0.0
    lon:       float = 0.0
    timeout:   float = 10.0
    user:      str = "publico"
    password:  str = "islas2026"
    _s: requests.Session = field(default_factory=_new_session)

    def __post_init__(self):
        self._s.auth = (self.user, self.password)

    def enviar(self, temperatura, humedad, salinidad, radiacion, estado="activo"):
        payload = {
            "device_id":   self.device_id,
            "lat":         self.lat,
            "lon":         self.lon,
            "temperatura": temperatura,
            "humedad":     humedad,
            "salinidad":   salinidad,
            "radiacion":   radiacion,
            "estado":      estado,
        }
        r = self._s.post(f"{self.base_url}/api/sensores", json=payload, timeout=self.timeout)
        r.raise_for_status()
        return r.json()


# ---------- uso ----------
cli = IslasClient(
    base_url="http://127.0.0.1:8000",
    device_id="sensor-07",
    lat=20.9742, lon=-89.6213,
)
cli.enviar(temperatura=34.8, humedad=48.2, salinidad=0.61, radiacion=820.0)

6 · Ejemplo real · Raspberry Pi + DHT22

Hardware real con sensor de temperatura/humedad conectado al GPIO de la Pi.

Python · rpi_dht22.py 
# pip install adafruit-circuitpython-dht requests
import time
import board
import adafruit_dht
import requests

API_URL   = "http://127.0.0.1:8000/api/sensores"
API_AUTH  = ("publico", "islas2026")
DEVICE_ID = "rpi-merida-01"
LAT, LON  = 20.9742, -89.6213

dht = adafruit_dht.DHT22(board.D4)

while True:
    try:
        t = dht.temperature
        h = dht.humidity
        if t is None or h is None:
            continue

        payload = {
            "device_id":   DEVICE_ID,
            "temperatura": round(t, 2),
            "humedad":     round(h, 2),
            "salinidad":   0.55,      # sensor capacitivo
            "radiacion":   750.0,     # piranómetro
            "lat": LAT, "lon": LON,
            "estado": "activo",
        }

        r = requests.post(API_URL, json=payload, auth=API_AUTH, timeout=10)
        print(f"[{time.strftime('%H:%M:%S')}] t={t:.1f}°C h={h:.1f}% → HTTP {r.status_code}")

    except RuntimeError:
        # DHT22 falla a veces, ignorar y reintentar
        pass

    time.sleep(60)

7 · Ingesta directa a Cosmos DB (sin pasar por la API)

Para cargas masivas, pruebas desde notebooks o procesos batch, también puedes insertar directamente en la colección SensoresRaw de Cosmos DB (API for MongoDB) usando pymongo. No requiere autenticación HTTP — usa las credenciales del propio cluster. Este patrón es ideal para Google Colab, scripts de simulación y migraciones.

Acceso privilegiado · solo para administradores
Este flujo salta la API REST y escribe directamente en la base. Úsalo solo para cargas iniciales, pruebas o migraciones. La cadena MONGO_URI contiene credenciales de administrador — no la subas a repos públicos ni la pegues en notebooks compartidos.
MONGO mongodb+srv://<cluster>.cosmos.azure.com / islas_calor.SensoresRaw

Inserta documentos con la misma estructura que el POST de la API, pero usando el driver de Mongo. El pipeline ETL los procesará en el siguiente ciclo (cada 5 min).

Consumir datos desde Python

Tres endpoints GET autenticados, devuelven JSON listo para cargar a pandas, numpy o cualquier herramienta de análisis.

Requiere autenticación HTTP Basic
Usuario: publico · Password: islas2026 (configurables vía API_USER / API_PASS en el .env). Pasa auth=(USER, PASS) a requests o -u USER:PASS a curl.
GET /api/sensores

Mediciones procesadas con features derivadas (UHI, zona térmica, índices).

GET /api/grid

2,500 puntos interpolados (IDW) del heatmap UHI.

GET /api/resumen

Estadísticas agregadas del último batch.

1 · Lectura básica

Python 
import requests

BASE = "http://127.0.0.1:8000"
AUTH = ("publico", "islas2026")     # (API_USER, API_PASS) del .env

sensores = requests.get(f"{BASE}/api/sensores", auth=AUTH).json()
grid     = requests.get(f"{BASE}/api/grid",     auth=AUTH).json()
resumen  = requests.get(f"{BASE}/api/resumen",  auth=AUTH).json()

print(f"Sensores: {len(sensores)}")
print(f"Grid: {len(grid)} puntos")
print(f"UHI promedio: {resumen['uhi_promedio']:.2f} °C")

2 · Cargar a Pandas + análisis

Python · analisis.py 
import pandas as pd
import requests

AUTH = ("publico", "islas2026")

df = pd.DataFrame(requests.get("http://127.0.0.1:8000/api/sensores", auth=AUTH).json())

# Promedios por zona térmica
print(df.groupby("zona_termica")[["temperatura", "uhi"]].mean().round(2))

# Sensores en zona crítica
criticos = df[df["uhi"] > 5].sort_values("uhi", ascending=False)
print(criticos[["lat", "lon", "temperatura", "uhi"]])

# Exportar a Excel
df.to_excel("sensores.xlsx", index=False)

3 · Visualizar heatmap localmente

Python · plot.py 
import numpy as np
import matplotlib.pyplot as plt
import requests

AUTH = ("publico", "islas2026")
grid = requests.get("http://127.0.0.1:8000/api/grid", auth=AUTH).json()
n = int(np.sqrt(len(grid)))

LATS = np.array([p["lat"] for p in grid]).reshape(n, n)
LONS = np.array([p["lon"] for p in grid]).reshape(n, n)
UHIS = np.array([p["uhi"] for p in grid]).reshape(n, n)

plt.figure(figsize=(10, 8))
plt.pcolormesh(LONS, LATS, UHIS, cmap="RdYlBu_r", shading="auto")
plt.colorbar(label="UHI (°C)")
plt.title("Islas de calor · Mérida, Yucatán")
plt.savefig("merida_uhi.png", dpi=200)
plt.show()
