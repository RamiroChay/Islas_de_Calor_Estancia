API Islas de Calor

API REST para la ingesta de mediciones ambientales desde sensores distribuidos y la consulta de datos procesados. Diseñada para dispositivos de bajo recurso (Raspberry Pi, ESP32 con MicroPython, gateways edge) que envían telemetría en formato JSON.

⚡
REST + JSON
Sin protocolos propietarios. Cualquier cliente HTTP funciona.
🔄
Procesamiento automático
El pipeline ETL corre cada 5 min sobre los datos crudos.
📍
Geo-referenciado
Cada medición incluye coordenadas (lat, lon) para interpolación espacial.

Base URL

Todas las rutas de esta API están prefijadas con la siguiente URL base:

https:// 127.0.0.1:8000

En producción, reemplaza por el dominio público de tu despliegue (p.ej. https://api.islasdecalor.org). El servidor expone CORS abierto para facilitar pruebas desde cualquier origen.

Autenticación

La API protege todos los endpoints /api/* con HTTP Basic Auth. Las credenciales se configuran en el archivo .env del servidor mediante las variables API_USER y API_PASS.

Credenciales por defecto (entorno de desarrollo):
Usuario publico · Password islas2026

Pasa las credenciales en cada llamada:

  • curl: -u publico:islas2026
  • Python requests: auth=("publico", "islas2026")
  • JavaScript fetch: headers: { Authorization: "Basic " + btoa("publico:islas2026") }
Cambia las credenciales antes de exponer la API a Internet. Genera un password aleatorio fuerte (openssl rand -base64 24) y actualízalo en .env + reinicia el servicio (systemctl restart islas-api o az webapp restart). Si despliegas en producción, asegúrate de servir siempre por HTTPS — Basic Auth viaja en texto plano sobre HTTP.

Enviar medición de sensor

POST /api/sensores

Recibe una medición individual desde un dispositivo sensor y la persiste en la colección SensoresRaw. El backend asigna automáticamente el campo timestamp (UTC) en el momento de la recepción.

Cuerpo de la petición

Content-Type: application/json

CampoTipoUnidadDescripción
device_idstring—Identificador único del sensor
temperaturanumber°CTemperatura ambiente
humedadnumber%Humedad relativa (0–100)
salinidadnumberratioSalinidad del suelo (0–1)
radiacionnumberW/m²Radiación solar
latnumber°Latitud WGS-84
lonnumber°Longitud WGS-84
estadostring—"activo" / "mantenimiento"

Esquema del payload del sensor

Todos los campos son requeridos para que el pipeline ETL pueda procesar la medición. Si un sensor falla en alguna lectura, omite el envío en lugar de mandar null — el pipeline elimina filas con valores faltantes durante la transformación.

device_id string
ID único del dispositivo. Usa un esquema consistente, p.ej. sensor-NN o mac:XX:XX:XX:XX:XX:XX.
temperatura float · °C
Rango esperado: 10 – 50 °C. Sensores recomendados: DHT22, BME280, DS18B20.
humedad float · %
Humedad relativa 0–100. Mismos sensores que temperatura.
salinidad float · ratio
Conductividad del suelo normalizada 0–1. Sensor recomendado: capacitivo + EC.
radiacion float · W/m²
Piranómetro o estimación desde LDR calibrada. Rango: 0 – 1200.
lat / lon float · WGS-84
Coordenadas fijas del sensor. Si es móvil, lectura del GPS al momento del envío.

Envío básico desde Python

Caso mínimo: leer un sensor, enviar una medición. Útil para pruebas de conectividad o dispositivos que despiertan, miden y vuelven a dormir.

Python · sensor_send.py 
import requests

API_URL = "http://127.0.0.1:8000/api/sensores"

payload = {
    "device_id":    "sensor-07",
    "temperatura":  34.8,
    "humedad":      48.2,
    "salinidad":    0.612,
    "radiacion":    820.5,
    "lat":          20.9742,
    "lon":         -89.6213,
    "estado":       "activo",
}

response = requests.post(API_URL, json=payload, timeout=10)
response.raise_for_status()
print("Enviado:", response.json())  # -> {'status': 'ok'}
Tip. Siempre pasa timeout a requests.post. Sin él, una API caída puede colgar un sensor IoT indefinidamente.

Envío continuo (loop de telemetría)

Caso típico: el dispositivo lee el sensor cada N segundos y envía la medición. Este patrón es lo que corre en producción dentro de los nodos físicos.

Python · sensor_loop.py 
import time
import requests

API_URL    = "http://127.0.0.1:8000/api/sensores"
DEVICE_ID  = "sensor-07"
LAT, LON   = 20.9742, -89.6213
INTERVALO  = 60  # segundos entre lecturas


def leer_sensor():
    """Reemplazar por la lectura real de los sensores físicos."""
    # Ejemplo con Adafruit_DHT (DHT22):
    #   import Adafruit_DHT
    #   h, t = Adafruit_DHT.read_retry(Adafruit_DHT.DHT22, 4)
    return {
        "temperatura": 34.8,
        "humedad":     48.2,
        "salinidad":   0.61,
        "radiacion":   820.0,
    }


def enviar(medicion: dict) -> bool:
    payload = {
        "device_id": DEVICE_ID,
        "lat":       LAT,
        "lon":       LON,
        "estado":    "activo",
        **medicion,
    }
    try:
        r = requests.post(API_URL, json=payload, timeout=10)
        r.raise_for_status()
        return True
    except requests.RequestException as e:
        print(f"[{time.strftime('%H:%M:%S')}] error: {e}")
        return False


if __name__ == "__main__":
    while True:
        med = leer_sensor()
        ok  = enviar(med)
        print(f"[{time.strftime('%H:%M:%S')}] t={med['temperatura']}°C  h={med['humedad']}%  ok={ok}")
        time.sleep(INTERVALO)

Reintentos y manejo de errores de red

Los sensores suelen estar en redes inestables (WiFi externo, LTE). Implementa reintentos exponenciales con un buffer local para que las mediciones no se pierdan cuando la API esté temporalmente caída.

Python · sensor_resiliente.py 
import json
import time
import pathlib
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

API_URL    = "http://127.0.0.1:8000/api/sensores"
BUFFER     = pathlib.Path("./pendientes.jsonl")

# 1 · sesión con reintentos automáticos (backoff exponencial)
session = requests.Session()
retries = Retry(
    total=5,
    backoff_factor=1.5,          # 1.5, 3, 4.5, 6, 7.5 s
    status_forcelist=[502, 503, 504],
    allowed_methods=["POST"],
)
session.mount("http://",  HTTPAdapter(max_retries=retries))
session.mount("https://", HTTPAdapter(max_retries=retries))


def guardar_buffer(payload: dict) -> None:
    """Persistir en disco si la API no respondió."""
    with BUFFER.open("a", encoding="utf-8") as f:
        f.write(json.dumps(payload) + "\n")


def vaciar_buffer() -> None:
    """Reintenta enviar los pendientes acumulados."""
    if not BUFFER.exists():
        return
    pendientes = BUFFER.read_text().splitlines()
    quedan = []
    for linea in pendientes:
        try:
            session.post(API_URL, json=json.loads(linea), timeout=10).raise_for_status()
        except requests.RequestException:
            quedan.append(linea)
    BUFFER.write_text("\n".join(quedan) + ("\n" if quedan else ""))


def enviar(payload: dict) -> None:
    try:
        session.post(API_URL, json=payload, timeout=10).raise_for_status()
        vaciar_buffer()
    except requests.RequestException as e:
        print("API caída, guardando localmente:", e)
        guardar_buffer(payload)


if __name__ == "__main__":
    enviar({
        "device_id":   "sensor-07",
        "temperatura": 34.8, "humedad": 48.2,
        "salinidad":   0.61, "radiacion": 820.0,
        "lat": 20.9742, "lon": -89.6213,
        "estado": "activo",
    })

Envío en batch (múltiples sensores)

Cuando un gateway recolecta mediciones de varios sensores (p.ej. por LoRa o BLE) y las reenvía en lote, el patrón es paralelizar las llamadas POST:

import requests
from concurrent.futures import ThreadPoolExecutor

API_URL = "http://127.0.0.1:8000/api/sensores"

mediciones = [
    {"device_id": "sensor-01", "temperatura": 33.1, "humedad": 52.0,
     "salinidad": 0.71, "radiacion": 780, "lat": 20.97,  "lon": -89.62, "estado": "activo"},
    {"device_id": "sensor-02", "temperatura": 36.4, "humedad": 41.5,
     "salinidad": 0.89, "radiacion": 910, "lat": 20.975, "lon": -89.63, "estado": "activo"},
    {"device_id": "sensor-03", "temperatura": 29.7, "humedad": 71.2,
     "salinidad": 0.32, "radiacion": 540, "lat": 20.965, "lon": -89.61, "estado": "activo"},
]


def enviar(med):
    r = requests.post(API_URL, json=med, timeout=10)
    return med["device_id"], r.status_code


with ThreadPoolExecutor(max_workers=8) as pool:
    for device_id, status in pool.map(enviar, mediciones):
        print(f"{device_id}: HTTP {status}")

Cliente reutilizable

Una clase pequeña que encapsula la sesión HTTP, ubicación fija del dispositivo y validación de campos. Recomendada para proyectos con varios scripts que envían datos.

Python · islas_client.py 
from dataclasses import dataclass
from typing import Optional
import requests


@dataclass
class IslasClient:
    base_url:   str = "http://127.0.0.1:8000"
    device_id:  str = "sensor-XX"
    lat:        float = 0.0
    lon:        float = 0.0
    timeout:    float = 10.0
    _session:   Optional[requests.Session] = None

    def __post_init__(self):
        self._session = requests.Session()

    def enviar(
        self,
        temperatura: float,
        humedad:     float,
        salinidad:   float,
        radiacion:   float,
        estado:      str = "activo",
    ) -> dict:
        payload = {
            "device_id":   self.device_id,
            "lat":         self.lat,
            "lon":         self.lon,
            "temperatura": temperatura,
            "humedad":     humedad,
            "salinidad":   salinidad,
            "radiacion":   radiacion,
            "estado":      estado,
        }
        r = self._session.post(
            f"{self.base_url}/api/sensores",
            json=payload,
            timeout=self.timeout,
        )
        r.raise_for_status()
        return r.json()

    def resumen(self) -> dict:
        r = self._session.get(f"{self.base_url}/api/resumen", timeout=self.timeout)
        r.raise_for_status()
        return r.json()


# ---------- uso ----------
if __name__ == "__main__":
    cli = IslasClient(
        base_url="http://127.0.0.1:8000",
        device_id="sensor-07",
        lat=20.9742, lon=-89.6213,
    )
    cli.enviar(temperatura=34.8, humedad=48.2, salinidad=0.61, radiacion=820.0)
    print(cli.resumen())

Ejemplo real: Raspberry Pi + DHT22

Integración completa con un sensor físico de temperatura/humedad (DHT22) conectado a una Raspberry Pi. El script lee el GPIO, normaliza, y envía a la API cada minuto.

Python · rpi_dht22.py 
"""
Hardware:
  - Raspberry Pi (cualquier modelo con GPIO)
  - DHT22 en GPIO 4 (temperatura + humedad)
  - LDR + ADS1115 para radiación aproximada (opcional)

Instalación:
  pip install adafruit-circuitpython-dht requests
  sudo apt install libgpiod2
"""
import time
import board
import adafruit_dht
import requests

API_URL   = "http://127.0.0.1:8000/api/sensores"
DEVICE_ID = "rpi-merida-01"
LAT, LON  = 20.9742, -89.6213

dht = adafruit_dht.DHT22(board.D4)


def leer_radiacion_aprox() -> float:
    """Stub — sustituir por lectura real del piranómetro."""
    return 750.0


def leer_salinidad_aprox() -> float:
    """Stub — sustituir por sensor capacitivo de suelo."""
    return 0.55


def medir_y_enviar():
    try:
        t = dht.temperature
        h = dht.humidity
    except RuntimeError as e:
        # DHT22 falla a veces — ignorar y reintentar al siguiente ciclo.
        print("lectura fallida:", e)
        return

    if t is None or h is None:
        return

    payload = {
        "device_id":   DEVICE_ID,
        "temperatura": round(t, 2),
        "humedad":     round(h, 2),
        "salinidad":   leer_salinidad_aprox(),
        "radiacion":   leer_radiacion_aprox(),
        "lat":         LAT,
        "lon":         LON,
        "estado":      "activo",
    }

    try:
        r = requests.post(API_URL, json=payload, timeout=10)
        r.raise_for_status()
        print(f"[{time.strftime('%H:%M:%S')}] enviado  t={t:.1f}°C  h={h:.1f}%")
    except requests.RequestException as e:
        print(f"[{time.strftime('%H:%M:%S')}] error API: {e}")


if __name__ == "__main__":
    while True:
        medir_y_enviar()
        time.sleep(60)
Estrategia de despliegue. Empaqueta el script en un systemd service para que arranque al boot y se reinicie si falla: /etc/systemd/system/islas-sensor.service.
Python · Consumir la API

Consulta básica de los endpoints

Para investigadores, periodistas o cualquier consumidor que quiera obtener los datos procesados desde Python. La API expone tres endpoints GET sin autenticación.

Python · consulta_basica.py 
import requests

BASE = "http://127.0.0.1:8000"

# 1 · Sensores con features derivadas
sensores = requests.get(f"{BASE}/api/sensores", timeout=10).json()
print(f"Sensores activos: {len(sensores)}")
print("Primer sensor:", sensores[0])

# 2 · Grid interpolado del heatmap (2,500 puntos)
grid = requests.get(f"{BASE}/api/grid", timeout=10).json()
print(f"Puntos en grid: {len(grid)}")

# 3 · Resumen global
resumen = requests.get(f"{BASE}/api/resumen", timeout=10).json()
print(f"UHI promedio: {resumen['uhi_promedio']:.2f} °C")
print(f"Zona dominante: {resumen['zona_dominante']}")
Tip. Los endpoints siempre devuelven el último batch procesado por el pipeline ETL. Para obtener datos históricos, consulta la base de datos MongoDB directamente o exporta snapshots periódicos.

Cargar la API a un DataFrame de Pandas

Para análisis tabular, lo más natural es cargar la respuesta de la API directamente a un DataFrame. Útil para estadísticas, agrupaciones, exportes y plots.

Python · cargar_pandas.py 
import pandas as pd
import requests

BASE = "http://127.0.0.1:8000"

# Construye DataFrame directamente desde el JSON
df = pd.DataFrame(requests.get(f"{BASE}/api/sensores", timeout=10).json())

print(df.head())
print(f"\nShape: {df.shape}")
print(f"Columnas: {list(df.columns)}")

# Estadísticas rápidas
print("\n--- Resumen estadístico ---")
print(df[["temperatura", "humedad", "uhi", "indice_vegetacion"]].describe())

# Sensores con UHI mayor a 5°C (zonas críticas)
criticos = df[df["uhi"] > 5].sort_values("uhi", ascending=False)
print(f"\nSensores en zona crítica: {len(criticos)}")
print(criticos[["lat", "lon", "temperatura", "uhi", "zona_termica"]])

Análisis & estadísticas descriptivas

Ejemplos comunes para investigación: agrupar por zona térmica, calcular correlaciones y detectar valores atípicos.

Python · analisis.py 
import pandas as pd
import requests

df = pd.DataFrame(requests.get("http://127.0.0.1:8000/api/sensores").json())

# 1 · Promedio por zona térmica
print("\n=== Promedios por zona térmica ===")
print(df.groupby("zona_termica")[["temperatura", "humedad", "uhi"]].mean().round(2))

# 2 · Comparativa urbano vs natural
print("\n=== Urbano vs Natural ===")
print(df.groupby("tipo_superficie").agg(
    sensores=("device_id", "count"),
    temp_promedio=("temperatura", "mean"),
    uhi_promedio=("uhi", "mean"),
    humedad_promedio=("humedad", "mean"),
).round(2))

# 3 · Correlación entre variables ambientales
print("\n=== Matriz de correlación ===")
cols = ["temperatura", "humedad", "radiacion", "salinidad", "uhi"]
print(df[cols].corr().round(2))

# 4 · Sensores en el percentil 90 de UHI
p90 = df["uhi"].quantile(0.90)
print(f"\nPercentil 90 de UHI: {p90:.2f}°C")
print(df[df["uhi"] >= p90][["lat", "lon", "uhi", "temperatura", "tipo_superficie"]])

Visualizar el heatmap localmente

Renderiza el grid interpolado con matplotlib para reproducir el mapa de calor en notebooks, papers o reportes.

Python · plot_heatmap.py 
import numpy as np
import matplotlib.pyplot as plt
import requests

# 1 · Datos
grid     = requests.get("http://127.0.0.1:8000/api/grid").json()
sensores = requests.get("http://127.0.0.1:8000/api/sensores").json()

lats = np.array([p["lat"] for p in grid])
lons = np.array([p["lon"] for p in grid])
uhis = np.array([p["uhi"] for p in grid])

# 2 · Reconstruir matriz cuadrada (50x50)
n = int(np.sqrt(len(grid)))
LATS = lats.reshape(n, n)
LONS = lons.reshape(n, n)
UHIS = uhis.reshape(n, n)

# 3 · Render
fig, ax = plt.subplots(figsize=(10, 8))
heatmap = ax.pcolormesh(LONS, LATS, UHIS, cmap="RdYlBu_r", shading="auto")
cbar = fig.colorbar(heatmap, ax=ax)
cbar.set_label("UHI (°C)", fontsize=11)

# 4 · Sobreponer sensores
for s in sensores:
    ax.scatter(s["lon"], s["lat"],
               c="white", edgecolors="black", s=80, zorder=5)
    ax.annotate(f"{s['temperatura']:.1f}°", (s["lon"], s["lat"]),
                xytext=(5, 5), textcoords="offset points", fontsize=8)

ax.set_title("Islas de calor urbanas · Mérida, Yucatán", fontsize=14, fontweight="bold")
ax.set_xlabel("Longitud")
ax.set_ylabel("Latitud")
plt.tight_layout()
plt.savefig("heatmap_merida.png", dpi=200)
plt.show()

Exportar a CSV / Excel

Snapshot completo de los datos en disco para análisis offline, archivo histórico o compartir con equipos no técnicos.

Python · export_snapshot.py 
"""
Crea un snapshot fechado de toda la información de la API.
Salida:  islas_calor_YYYY-MM-DD/
            ├── sensores.csv
            ├── grid.csv
            ├── resumen.json
            └── reporte_completo.xlsx
"""
import json
import requests
import pandas as pd
from datetime import datetime
from pathlib import Path

BASE = "http://127.0.0.1:8000"

# 1 · Descargar
sensores = requests.get(f"{BASE}/api/sensores").json()
grid     = requests.get(f"{BASE}/api/grid").json()
resumen  = requests.get(f"{BASE}/api/resumen").json()

# 2 · Carpeta de salida
fecha = datetime.now().strftime("%Y-%m-%d")
out   = Path(f"islas_calor_{fecha}")
out.mkdir(exist_ok=True)

# 3 · CSV

Consulta asíncrona (aiohttp)

Cuando se necesita consultar muchos endpoints en paralelo o integrar con un servicio asíncrono (bot, API gateway, scraper), aiohttp reduce drásticamente el tiempo total.

Python · async_fetch.py 
import asyncio
import aiohttp

BASE = "http://127.0.0.1:8000"
ENDPOINTS = ["/api/sensores", "/api/grid", "/api/resumen"]


async def fetch(session, path):
    async with session.get(f"{BASE}{path}", timeout=10) as r:
        return path, await r.json()


async def main():
    async with aiohttp.ClientSession() as session:
        resultados = await asyncio.gather(*[fetch(session, p) for p in ENDPOINTS])

    for path, data in resultados:
        size = len(data) if isinstance(data, list) else 1
        print(f"{path:25s} → {size} registros")
    return dict(resultados)


datos = asyncio.run(main())
print(f"\nUHI promedio actual: {datos['/api/resumen']['uhi_promedio']:.2f} °C")
Dependencias. pip install aiohttp

Polling continuo & monitoreo

Watcher que consulta el resumen cada N segundos y alerta cuando el UHI máximo cruza un umbral configurable. Útil para integraciones con Slack, email o sistemas de alerta temprana.

Python · monitor.py 
import time
import requests
from datetime import datetime

BASE         = "http://127.0.0.1:8000"
UMBRAL_UHI   = 8.0   # °C — alertar cuando UHI máximo supere este valor
INTERVALO    = 60    # segundos

estado_previo = None


def check():
    global estado_previo
    try:
        r = requests.get(f"{BASE}/api/resumen", timeout=10).json()
        uhi_max = r.get("uhi_max", 0)
        zona    = r.get("zona_dominante", "—")
        ts      = datetime.now().strftime("%H:%M:%S")

        alerta = uhi_max >= UMBRAL_UHI
        estado = "ALERTA" if alerta else "ok"

        print(f"[{ts}]  UHI_max={uhi_max:.2f}°C  zona={zona}  → {estado}")

        # Notificar cambios de estado (transición)
        if alerta and estado_previo != "ALERTA":
            print(">>> ALERTA · Umbral de UHI superado")
            # aquí: enviar webhook a Slack, email, etc.
        estado_previo = estado

    except requests.RequestException as e:
        print("error:", e)


if __name__ == "__main__":
    while True:
        check()
        time.sleep(INTERVALO)
Producción. Para alertas en sistemas críticos usa tenacity o backoff para reintentos robustos, y persiste el estado en disco para sobrevivir reinicios.

Pipeline interno de procesamiento

Cuando un sensor envía datos, el flujo completo es:

  1. Ingesta — POST /api/sensores inserta en SensoresRaw (MongoDB).
  2. Extract — cada 5 min el scheduler lee todos los documentos crudos.
  3. Transform — calcula UHI, normalizaciones, índices y clasifica zonas térmicas.
  4. Load features — escribe en mediciones_analitica.
  5. Interpolación IDW — genera 2,500 puntos para el heatmap.
  6. Load grid + resumen — escribe mapa_calor_actual y resumen_ambiental.
  7. Exposición — los endpoints GET sirven el último batch al frontend.
Tiempo hasta verse en el dashboard. Hasta 5 minutos (latencia del scheduler). Para procesamiento inmediato, ejecuta manualmente python -m dags.weather_pipeline.
